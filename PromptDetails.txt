## TASK
Extract Trinity's validation responses from the email body provided below and return 
them as a JSON array of exactly 9 objects — one per validation item — in the exact order, 
using the exact "pyName" and "pyDescription" values defined in the schema.

## REQUIRED JSON SCHEMA
The output structure (pyName, pyDescription, pyValue for each of the 9 validation items) 
is defined in this property: {.ValidationFlags.pyAIAssistedField}
Use that structure exactly as given. Do not add, remove, rename, or reorder fields or rows. 
Leave "pyName" and "pyDescription" unchanged. Fill only "pyValue" for each row with what 
Trinity entered in the "Trinity Response / Details" column for that item.

## ORIGINAL EMAIL BODY
{.ValidationFlags.pyMessageBody}

## EXTRACTION RULES
1. Locate each validation item by matching its exact label text (e.g. "Is the policy 
   number valid?") in the email body, and extract whatever Trinity wrote in the response 
   column/cell associated with that item.
2. Extract the LITERAL, VERBATIM text Trinity typed — in full, exactly as written. The 
   "pyDescription" values (e.g. "Yes / No / Unable to Confirm") are a format guide only, 
   not a list to classify the answer into. Never truncate, paraphrase, or round the 
   response to the nearest listed option. If Trinity wrote "Unable to Confirm at this 
   time", extract the full phrase — not just "Unable to Confirm" or "Unable to".
3. Strip all HTML tags, attributes, inline styles, and markup (<p>, <span>, <div>, <br>, 
   <font>, style="...", class="...") from the extracted value. Decode HTML entities 
   (&nbsp; → space, &amp; → "&", etc.). Return clean plain text only — never raw or 
   partially-stripped HTML.
4. If a single response is split across multiple HTML tags, spans, or line-wrapped 
   elements — even mid-word or mid-phrase — concatenate ALL text within that table cell 
   into one continuous string, in original order, separated by a single space. Read the 
   full cell from its opening tag to its closing tag; never stop at the first inner tag.
5. If the email contains multiple copies of the table (e.g. quoted/forwarded content), 
   use only the most recent reply — the one appearing above any "From:" / "Original 
   Message" / quoted-thread markers.
6. If a specific row's response is genuinely blank, missing, or not present in the email, 
   set "pyValue" to "" for that row only. Do not omit the row or return null.

## EXAMPLE
If the email cell contains: <td><span>Unable to</span> <span>Confirm</span> - pending 
underwriter response</td>
Correct pyValue: "Unable to Confirm - pending underwriter response"
Incorrect pyValue: "Unable to" (do not truncate like this)

## ERROR RESPONSE
If the requested extraction cannot be completed, do not return the normal output schema. 
Instead, respond ONLY with the JSON structure defined in property 
{.PolicySchedule.AIErrorJSON}.

Return the error JSON only when:
- The email body is empty, missing, or contains no readable text
- No validation table (or table-like content) matching the expected validation items can 
  be found anywhere in the email body
- The email body is unrelated to the validation request (e.g. an out-of-office reply, a 
  bounce/delivery-failure notice, spam, or a message that does not reference any of the 
  9 validation items)
- None of the 9 validation items can be matched with reasonable confidence anywhere in 
  the content

Do NOT return the error JSON merely because some individual rows are blank — partial 
responses are valid and normal. Only use the error path when the email as a whole cannot 
be matched to the validation table at all.

For error responses:
- Return ONLY the error JSON structure, fully populated (ErrorCode, ErrorCategory, 
  ErrorMessage).
- Do not return markdown or explanatory text outside the JSON.
- Do not mix the success JSON and error JSON in the same response.

## OUTPUT FORMAT
Return ONLY the JSON (success schema or error schema, never both). No markdown, no code 
fences, no preamble, no explanation, no text before or after the JSON.
